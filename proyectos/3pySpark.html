PySpark Transaction Analysis Pipeline

  • Python, PySpark, Spark SQL
  • Big Data Processing
  • 2026
  • EN, ES

The problem

Consumer data is scattered across transaction logs—each entry records who spent what, using which payment method, across multiple sources. Traditional tools struggle because the data is too large to load into memory, but the questions are simple: Which payment methods do people actually use? Which video categories attract the most viewers? How do spending patterns differ based on payment method and amount? These require aggregation across millions of records without overwhelming a single machine.

What I built

A three-stage PySpark pipeline that analyzes consumer spending behavior. The first job filters out credit card transactions and aggregates spending by person using non-credit methods (Bizum, cash, etc.), revealing who avoids debt-based payments. The second finds the video category with the highest total views by parsing log files with multiple delimiters and summing views by category type. The third segments users based on credit card spending thresholds: those with purchases over 1500 versus those under, uncovering spending tier patterns. Each job demonstrates core PySpark patterns: map transformations for parsing, filter for conditional logic, reduceByKey for aggregation, and cache for reusing RDDs across operations.

Outcome

A practical understanding of PySpark's lazy evaluation model and how RDD transformations compose into efficient execution plans. The output segments users by behavior (credit vs non-credit spending, high-value vs low-value transactions) and identifies consumption trends (dominant video categories). More importantly, I learned how to think in terms of distributed transformations: instead of writing loops that process rows sequentially, you declare how data should flow through map and reduce stages, then let Spark decide how to parallelize it. This mental model transfers directly to larger datasets without code changes.
