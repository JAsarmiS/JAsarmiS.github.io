Open Data ETL Pipeline for Surgical Waiting List

  • Python, Pandas, MongoDB
  • Data Engineering
  • 2026
  • EN, ES

The problem

Open data portals publish health and economic datasets in inconsistent formats. The Valencian Government's surgical waiting list dataset came as embedded JSON inside a CSV file, with data structured at the cell level rather than the row level: 80% of cells were null because each value occupied its own row. Before I could analyze patterns in surgical delays, I needed to extract the data from an official API, normalize the malformed structure into proper database records, and load it somewhere I could visualize it. The real challenge was not the data itself but learning to handle the messy reality of real-world open data.

What I built

An end-to-end ETL pipeline from raw data to interactive dashboards. I started with automated extraction from the CKAN API, downloaded datasets in multiple formats (CSV, JSON), and identified the structural problems using exploratory analysis with Pandas. The pathology dataset required custom normalization logic to reconstruct complete rows from scattered cells.

Once clean, I loaded both datasets into MongoDB Atlas collections and built five MongoDB Charts visualizations that revealed patterns hidden in the raw numbers: which surgical procedures face the longest waits, which hospitals have the most acute bottlenecks, and how delays vary by specialty and region.

Outcome

A working knowledge of the full data pipeline: extraction, validation, transformation, loading and visualization. The analysis surfaced concrete insights into the Valencia health system: plastic surgery and neurosurgery wait times exceed 120 days while cardiovascular surgery stays low due to clinical urgency. I also practiced working with NoSQL databases, cloud data platforms and querying large datasets efficiently. This was my first real encounter with messy data and the skills needed to make it analysis-ready.
